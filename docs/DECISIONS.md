# Decisions (ADR-lite). Do not reopen without a new entry.

D-01 KMP + Compose Multiplatform over Flutter — owner's Kotlin expertise, YFT code reuse.
D-02 Project-as-folder with immutable content-hash artifacts; SQLite only as index.
D-03 Stale detection via recorded inputs, not status cascades.
D-04 Video generation is manual via Google Flow. No automation of Google UIs — ToS/account risk and brittleness.
D-05 Gemini API free tier (AI Studio key) for text/image/TTS. AI Pro subscription is NOT an API credential; it only applies to Flow/AI Studio UI.
D-06 No backend, accounts, billing, or custom sync. Syncthing/folder copy is the sync method.
D-07 Desktop video playback: VLCJ first. Fallback if spike S3 fails: ffmpeg-extracted thumbnails + "open externally", playback deferred.
D-08 ~~Android does not render. ffmpeg-kit is retired; Media3 Transformer only for preview concat if ever needed.~~ Amended by D-22/D-23 (2026-11-11): Android renders; ffmpeg-kit stays retired.
D-09 Voice replication is an optional, capability-gated feature. Default narration path is user recording; standard TTS second.
D-10 Model names/quotas/credit costs live in `config/models.json`, never in code.
D-11 Koin for DI (KMP). kotlinx.serialization for all persisted models.
D-12 Burmese text for humans, English for models; separate fields, never auto-translated silently.
D-13 Toolchain pinned as one set in `gradle/libs.versions.toml` only: Kotlin 2.4.21, Compose Multiplatform 1.12.2, AGP 9.3.3, Gradle 9.7.1, kotlinx.serialization 1.12.0, coroutines 1.11.0, Ktor 3.6.1, Koin 4.2.2 (newest set inside Kotlin 2.4.21's tested Gradle/AGP range); shared modules use `com.android.kotlin.multiplatform.library` + `jvm("desktop")`; JVM target 17, minSdk 26, compileSdk 37; no Material3 (custom theme per DESIGN.md); upgrade versions together as a set.
D-14 Reference images: manual handoff by default — copy the ImageDialect prompt, generate in the AI Studio UI or Flow (covered by the AI Pro subscription), import the file as Ref A/B. `GeminiImageProvider` is optional and capability-gated: a probe that returns 429 with `limit: 0` marks it unavailable. Reason: spike S2 — every Gemini image model has zero free-tier API quota, and D-05/D-06 rule out API billing.
D-15 GeminiTextProvider resilience: the model fallback chain is the stage's ordered `candidates` list in `config/models.json` (never in code), applied at every stage call; exponential backoff on 500/503 (and on 429 when `retryDelay` ≤ 60 s); request timeout 120 s per attempt, and every running AI call shows a Cancel button; app-side daily request counter, because the API returns no rate-limit headers. Reason: spike S1 — `gemini-2.5-flash` refused for new keys, `gemini-3.8-flash` mostly 503, and 3.5-flash 503 on about half of calls. (Amended 2026-11-10: timeout 300 s → 120 s + Cancel; chain source = `candidates`.)
D-16 VLC is not bundled. Playback uses a separately installed VLC 3.0.x (64-bit): Settings → "VLC path", auto-detected at `C:\Program Files\VideoLAN\VLC`. If VLC is not found, show an "Install VLC" link (videolan.org) and disable playback; shots show ffmpeg-extracted thumbnails only. Reason: spike S3 — even a trimmed VLC adds ≈95 MB to the installer plus LGPL/GPL plugin licensing; VLCJ JARs (3.7 MB) stay in the app. Closes Q-05.
D-17 Test-only libraries: `kotlinx-coroutines-test` (virtual time for retry/backoff and fake-delay tests) and `ktor-client-mock` (HTTP-free provider tests). Versions come from the D-13 `kotlinx-coroutines` / `ktor` refs; never on a main classpath.
D-18 File access: `:core` owns the small `core.io.FileSystem` port (exists/createDirectories/list/read/writeDurably/atomicMove; `watch` added with the Inbox in 1C-d) with `InMemoryFileSystem` for tests. `:platform` implements `JvmFs` (java.nio: `FileChannel.force` + `ATOMIC_MOVE`) in a source set shared by desktop and Android, which adds the `:platform → :core` edge. Android SAF arrives in 1F (optional, D-25) as another implementation; `:core` does not change. Closes Q-06.
D-19 API key storage on Windows: JNA (`jna` + `jna-platform` 5.17.0, desktop only) for DPAPI `CryptProtectData` (current-user scope); `SecureStorage` keeps the encrypted blob in `~/.autoflow/secrets.bin` (atomic write). Simpler than Credential Manager with the same per-user binding. Other desktop OSes report `Unsupported` (no env-var fallback, AGENTS.md §1), so Real AI mode needs Windows. Android: see D-25.
D-20 Amends D-02: the project index is a rebuildable JSON list `~/.autoflow/projects.json` (path, name, mode, ratio, progress, last opened), not SQLite, until project counts need more. No new dependency; losing it loses no data (re-open the folders).
D-21 A shot whose spec id changes (regenerate all/one, edit, version switch) loses only its storyboard approval; prompt/ref/video pointers and approvals stay and show as stale (specs/workflow-and-approval.md "Approvals are not auto-cleared"). Storyboard versions (`sb`) are whole-song generations; per-shot regenerates and edits record `inputs.storyboard` = the current version and are not added to it.
D-22 Android is a first-class target, equal to desktop (2026-11-11): the owner has no PC, so the phone does everything — Gemini API, Flow in the mobile browser, import, render, export. The Phase 3 "companion" scope is replaced by full feature parity (PLAN 1F); Windows stays supported and is verified by CI only. Amends D-08: Android renders. On-device testing has no adb: the owner installs a CI-built APK (D-24) and pastes back a report the app writes (Self-test, PLAN S6; crash text on the next launch).
D-23 Android rendering runs a bundled ffmpeg executable, driven by the same RenderGraph → filtergraph compiler as desktop (one compiler in `:media` commonMain). The binary is `app-android/src/main/jniLibs/arm64-v8a/libffmpeg.so` (plus `libffprobe.so`), packaged with `useLegacyPackaging = true` so Android extracts it to `applicationInfo.nativeLibraryDir` — the only app location Android 10+ (targetSdk ≥ 29, W^X) lets an app exec — and started with `ProcessBuilder`. Source: built by our CI (`tools/ffmpeg-android/`) from upstream release tarballs pinned by SHA-256 (FFmpeg 9.0.2 with libx264, libass + freetype + fribidi + harfbuzz, native `aac`; no fontconfig: fonts come only from `fontsdir`, specs/render-graph.md), NDK r29, arm64-v8a, API 26, PIE against bionic, third-party libraries static; not committed (binary), cached in CI. License: GPL-2.0-or-later (libx264), license texts and the build info (configure line, source URLs, hashes) ship in the APK. Size: ≈ 25 MB each for `libffmpeg.so` and `libffprobe.so` uncompressed (first build 2026-11-11; exact bytes, SHA-256 and linked system libraries are in the APK `assets/ffmpeg/BUILDINFO.txt` and the CI "Bundled ffmpeg" notice); only Android system libraries are linked dynamically. Why not a download: ffmpeg-kit is retired (D-08) and static glibc Linux builds risk being killed by Android's app seccomp filter. If the from-source build cannot be made to work, a pinned Termux ffmpeg package (libass) is the recorded fallback. Media3 Transformer 1.11.1 (`media3-transformer`, `media3-effect`, `media3-common`) is a fallback only if exec is blocked on the owner's device; the Self-test runs it when exec fails. Verified 2026-11-11 (S6 PASS on the owner's Android 16 phone, spikes/s6-android-selftest/README.md): exec is the render path.
D-24 Every CI push builds a debug APK and uploads it as the Actions artifact `autoflow-debug-<sha>.apk`; a tag `v0.*` attaches it to a GitHub Release so the owner downloads it on the phone. The agent cannot push tags, so a change to `.github/release-tag.txt` on `main` makes that CI run create the tag and the release (tags made with the workflow token start no new workflow runs). Signing: one stable key from Actions secrets (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), never committed, so every APK installs over the previous one and app data survives; without the secrets the build falls back to the runner's debug key and says so in the APK's build info. `versionCode` = CI run number.
D-25 Android platform choices: playback = Media3 ExoPlayer (no VLC on Android, D-16 is desktop only). Secure storage = Android Keystore AES-256-GCM key (non-exportable) encrypting the existing `FileSecureStorage` blob — the platform API directly, not `androidx.security:security-crypto` (deprecated). Project folders live under the app's external files dir by default (no SAF needed); SAF "Open folder" is optional later. Uninstalling deletes that dir, so Settings gets "Backup all projects" (zip → share sheet) (PLAN 1F). Secure-storage details (2026-11-11): the cipher is `AesGcmCipher` (`:platform` jvmShared, so it is tested on the JVM with a software key): `secrets.bin` = `AFS1` · version `1` · 12-byte IV (chosen by the Keystore) · ciphertext + 128-bit tag, with a fixed AAD; key alias `io.github.alalkipgen.autoflow.secrets.v1`, no user authentication (renders and the AI run without unlocking). The key never leaves the phone, so `secrets.bin` is excluded from Auto Backup and device transfer (manifest rules); a file without its key reads as unreadable and the next save replaces it with a new key.

D-26 Android render scheduling (2026-11-11): AndroidX WorkManager 2.12.0 runs renders as durable background work in its foreground service (progress + Cancel notification; `mediaProcessing` type on Android 15+, `dataSync` before). WorkManager brings Room, AndroidX Startup and lifecycle-service transitively. One unique chain `render` (APPEND_OR_REPLACE) keeps renders one at a time and in order. A failed or cancelled WorkManager work fails or cancels every work queued behind it, so (1) every render ends as a succeeded work with its outcome (done / failed / cancelled) in the output Data, and (2) Cancel never calls WorkManager's cancel: a per-job marker (`filesDir/render-jobs/<id>.cancel`) makes a queued job skip itself, and the running render's coroutine is cancelled in-process, which kills ffmpeg; the worker returns only after that, so two renders never overlap. When WorkManager itself stops the worker, the cancellation is rethrown and WorkManager retries it. The job JSON lives in `filesDir/render-jobs/<work id>.json` (Data is limited to 10 KB) and is deleted only when WorkManager no longer lists the work as unfinished and the file is over an hour old, so a retry after process death still finds it. Rejected: one long-running drain worker over our own queue file (a second source of truth beside WorkManager). Tests are JVM unit tests with fakes; `kotlin-test-junit` (test only, JUnit 4 for Android local unit tests) is the only added test dependency.

D-27 Android project storage and backup (2026-11-11, details D-25): new projects go to `<external files dir>/projects/<name>.autoflow` (`AppDirs.projectsHome`; the internal files dir if there is no external storage) without a folder choice; the Dashboard hides "Open folder…" and adds `*.autoflow` folders it finds there to the list, so a lost `projects.json` or a restored backup reappears. Settings → Backup zips every listed project whose `project.json` exists (`ProjectZip`, java.util.zip: `<folder>.autoflow/…` + `autoflow-backup.json` manifest; leaves out `.cache/`, `*.part.*`, `*.tmp`; media stored, text deflated) straight into `Download/AutoFlow/AutoFlow-backup-<yyyyMMdd-HHmmss>.zip` through MediaStore (Android 10+, no storage permission, visible in the Files app, kept after an uninstall; older Android reports Unsupported), with a free-space check first and the half-written file deleted on failure or Cancel; "Share…" then sends that file to the share sheet. Saving to Download instead of a cache file + share sheet only means one uninstall-proof copy always exists. Restore arrives with the system file picker (PLAN 1F). No new dependency.

D-28 CI build-machine ffmpeg (2026-11-11): the android job gets the x86-64 ffmpeg for the S6 self-test media from a pinned static build (johnvansickle.com ffmpeg 7.0.2-static, GPL, SHA-256 checked; libx264, libmp3lame, libass) via `tools/ci-ffmpeg.sh`, with bounded apt (`tools/ci-apt-install.sh`) as the fallback. Why: the Ubuntu apt mirror hung every android job on 2026-11-11. CI only — nothing is shipped in the app; the phone keeps the D-23 bundled ffmpeg.

D-29 Prompt staleness inputs (2026-11-12, Q-10, owner approved): a compiled prompt (`pr`) records `spec`, `globalStyle` and — new — `characters` = `"<sorted tokens>|ch_<12 hex>"` (the tokens the shot uses and a SHA-256 of their current English descriptions), so changing a character's description marks exactly the prompts that use it ⚠ Stale. When a recompile produces bytes identical to an existing `pr` artifact (dedupe), `ArtifactStore.recordInputs` rewrites only that sidecar's `inputs` (atomic); data files stay write-once. Rejected: hashing all characters (one edit would stale every shot).

D-30 Lyric line timings (2026-11-12, Q-11, owner approved): the song's line timings are one `tx` artifact (`LyricTimings {schemaVersion, source: "tap"|"gemini", lines: [{text, startMs, endMs}]}`, song time) pointed to by the new optional `project.lyricTiming` (no schema bump: the field defaults to null). Lines = the lyrics' non-blank lines without `[Section]` markers. They are used only while they match the current lyrics lines; otherwise Export falls back to each shot's `lyricsMy` and says so. Importing another song clears the pointer. With timings, Export shows one overlay per line at its own time (cut at the video's end) instead of one per shot; shot cut points do not change (snapping cuts to line starts is a later option). Tap-to-sync: a line ends where the next starts, at most 10 s; the last ends at an extra "end" tap (else 6 s, cut at the song end); taps < 150 ms apart are ignored. Desktop has no audio player (no VLC binding), so tap-to-sync is Android-only for now.

D-31 Gemini lyric timing (2026-11-12, Q-11 steps 2–3): `TranscribeProvider.transcribe(audio, lang, mime, lines)` — with known lyric lines it aligns them (one segment per line, in order). The real one is `GeminiTranscribeProvider`: the song is decoded by ffmpeg to 16 kHz mono WAV (`.cache/lyrics-ai.wav`, about 1.9 MB/min; else the song file itself when its type is mp3/wav/ogg/flac/aac/m4a) and sent inline (≤ 14 MB) with the numbered lines to the `text` model chain (structured output `{lines:[{line,start,end}]}` in seconds); an answer that misses or repeats a line counts as invalid and is retried / falls back. The app cleans it (`LyricSync.suggested`: increasing starts, end by the next start, 10 s cap) and saves it as the same `tx` timings with `source: "gemini"`; the owner checks on Export → Preview and re-taps if needed. S7 (measure Burmese timing error on one real song) runs on the owner's phone with this button, because the song and the key are there; until then the button is labelled as a suggestion and tap-to-sync stays the reliable path.

D-32 Snap cuts to beat (2026-11-12, Q-12, owner approved (b)): Storyboard header switch "♩ Snap cuts to beat" = `settings.snapToBeat`. Beats come from our own Kotlin tracker in `:media` (`BeatDetector`: ffmpeg decodes the song to 11 kHz mono WAV, Hann FFT 1024 / hop 256 spectral-flux onsets, autocorrelation tempo 60–200 BPM weighted towards 120, Ellis dynamic-programming beat tracking) and are cached in `.cache/beats.json` with the song's SHA-256. On: each cut moves to the nearest beat within ±250 ms unless a shot would get shorter than 2 s (or shorter than it was) — `BeatSnap` in `:core`; the storyboard version keeps its own cuts, so Off restores them exactly, and a new / switched version snaps again while On. Only `startMs` / `durationMs` change: approvals, specs, prompts and videos stay (a prompt's whole-second duration can differ by one second; recompile if that matters). Rejected: a beat-detection library (new dependency, Android NDK) and snapping in ShotSplitter (the beats would be needed before the AI storyboard).

D-33 Movie Recap scope (2026-11-12, Q-13; owner: "finish everything up to Phase 4", i.e. the proposed order): docs/specs/recap.md. Own/licensed footage only, with a required rights tick on New Movie Recap and the notice repeated on the Recap and Export screens; the movie is streamed into `source/movie.<ext>` (not an artifact: too large to hash) and never uploaded. Script input = typed summary and/or `.srt` (no Gemini Files API: no movie upload, no extra quota); one narration segment per picked scene, stored as a new `rs` artifact kind. Built in slices: (a) movie import + ffmpeg `scdet` scenes + picker, (b) script + approval, (c) voice, (d) fit check + captions + looks + export through the existing Export screen. Gates live in `:core` `RecapRules`.

D-34 Voice sources (2026-11-12): Recorded (default, D-09; Android `MediaRecorder` with the RECORD_AUDIO permission, desktop `javax.sound`, or an imported file) and Gemini TTS (`GeminiTtsProvider`, prebuilt voices, models from `config/models.json` `tts.candidates`). Gemini voice replication needs a paid-tier project (Gemini API docs, 2026-11) and the owner uses the free tier (D-05), so Replicated stays hidden while `tts.replication` ≠ `"available"`; S5 becomes a Settings button that speaks one Burmese sentence.

D-35 TTS voice lock (2026-11-13, owner approved Phase 5; amends D-15 / D-34 for TTS): `config/models.json` `tts.candidates` becomes a list of `{ "id", "langs" }` — the languages each model can speak, copied from the Gemini speech-generation table (checked 2026-11: `gemini-3.8-flash-tts` lists Burmese, `gemini-3.8-flash-lite-tts` does not); a model without the script's language is never used for it, and `tts.burmese` goes away. A Recap project has one `recap.voiceLock = {provider, model, voice, lang}`: picked on the Voice step (default: the first candidate that speaks the language, voice Charon), or set by the first TTS take if still empty. Every TTS call of the project uses exactly the lock: 429 / 500 / 503 get the D-15 backoff, then the job pauses ("<model> is busy — Resume") — never a silent switch to another model or voice; a model that no longer exists fails the job with "Change voice…". "Change voice…" is explicit and asks: re-speak all (N requests, ETA) or keep the old takes, which then show "Different voice". Every take records provider / model / voice; Export pre-flight warns about mixed or unknown voices. Settings → Test Gemini TTS (S5) lists only models that speak Burmese. Reason: the current chain (3.8 Flash TTS → 3.8 Flash-Lite TTS → 2.5 Flash preview TTS, all treated as Burmese-capable) can switch model and voice in the middle of Speak all after a 503, and takes do not record which model spoke. Ships first, without a flag (bug fix).

D-36 Recap data v2 (2026-11-13, docs/specs/studio-v2.md §2): the recap script becomes a story of blocks — a new `rs` schemaVersion 2 `{source, style, register, blocks:[{id, clips:[{inMs, outMs}], textMy, speakMy}]}`: a block plays one or more movie ranges (split, merge, reorder, trim without re-finding scenes) and has a stable id (`b_` + 8 hex), so takes belong to a block, not to an index. `project.recap` v2: `story` + `storyApproved` replace `script` + `scriptApproved`; takes become `{block, audio, source, provider, model, voice, durationMs, spokenHash, createdAt}`; new `sources`, `voiceLock` (D-35), `fit` (D-46), `layers` (D-37), `audio`, `captions`, `quality`. `spokenHash` = SHA-256 (12 hex) of the text actually spoken (`speakMy` or `textMy`, after the Lexicon, D-39), so a lexicon edit marks exactly the affected takes ⚠ Stale. `project.json` `schemaVersion` 1 → 2 with a `:core` `Migration` (project-format.md rule), run once on open: `project.json` is first copied to `project.v1.bak.json`; each v1 segment becomes one block with one clip = its scene; takes map by index; the approval is kept (the text did not change); old TTS takes get `model: null` ("voice unknown"); Music Video projects only change the number. v1 `rs` artifacts stay untouched (immutable). An older app cannot open a v2 project (release notes: back up first). Rejected: blocks inside `project.json` (would lose the per-edit artifact history D-02 gives scripts).

D-37 Layer model (2026-11-13, spec §4): blur masks, logo / watermark images, title text, border and background are `recap.layers` items `{id, type: BLUR | IMAGE | TEXT | BORDER | BACKGROUND, rect: [x, y, w, h] in 0–1 of the output frame, fromMs, toMs, params}`; caption placement uses the same rect form. One model, two renderers: the existing RenderGraph → filtergraph compiler for export (`crop` + `gblur` + `overlay`, `overlay`, libass, `drawbox` / `pad`, a scaled blurred copy for BACKGROUND) and Compose drawing for the live preview (D-42). Relative coordinates fit every ratio and 720 / 1080 / 1440. The bundled ffmpeg already has these filters (D-23); no new dependency. Golden tests on the compiled filtergraph strings.

D-38 Jobs (2026-11-13, spec §5): one Jobs list for long work. Renders keep the WorkManager `render` chain (D-26); AI batches (Speak all, Transcribe, Quick Recap stages, Publish Kit) run on a second unique chain `ai` (network work, so it can run beside a render) with the same foreground-notification, job-JSON and cancel-marker rules (`filesDir/ai-jobs/`). AI jobs are resumable and idempotent: a TTS job is a list of block ids and skips every block whose newest take is current (spokenHash + voiceLock), so a killed app resumes where it stopped. Pacing: `rpm` per stage in `config/models.json` (data; TTS starts at 3 because the free tier allows only a few TTS requests a minute — the exact limit is per project in AI Studio) and the 429 `retryDelay`; before start the card shows requests, ETA and today's count (`UsageCounter`, D-15). Desktop runs the same runner in-process. Home and the nav show a Jobs badge.

D-39 Library (2026-11-13, spec §6): app-level Brand Kits (logo, watermark, colours, font, caption style, layer preset, intro / outro), Voices (saved voice locks), Lexicon (written → spoken Burmese), Music, Fonts and Presets in `<app data>/library/` (`library.json` + `files/`, atomic writes; desktop `~/.autoflow/library/`, Android `filesDir/library/`). A project never points into the Library: applying a kit or preset copies the files into the project's `artifacts/` (`im`, `au`, new kind `ft` font) and the values into `project.json`, so a project folder stays complete (D-02) and a later Library edit never changes a finished project. Backup (D-27) adds `library/` to the zip; restore merges by id.

D-40 UI v2 (2026-11-13, DESIGN.md §7; amends DESIGN.md §2 / §4): top level = Home · Projects · Library · Jobs (phone: bottom nav; ≥ 600 dp: nav rail; ≥ 840 dp: project screens in three panes, list · editor · preview). One set of composables for every width — no separate desktop design (D-22: the phone is the main device, Windows is checked by CI). Recap = five steps Source · Story · Voice · Style · Export with a "Voice · 3/5" step header instead of a tab bar (Burmese labels at the owner's large font size do not fit six tabs); the Story list opens a block editor; Voice & Audio opens for one block and returns to it. Music Video = one Shot sheet per shot (storyboard text, prompt, refs, Flow handoff, versions) instead of separate Storyboard / Shots / Handoff screens. The mockups in `docs/mockups/phase5.html` are AI-drawn with English labels — the app uses Burmese strings (DESIGN.md §6).

D-41 Feature flags and release (2026-11-13): Phase 5 lands one task per PR on `main`, each checked on the owner's phone with the CI APK (D-24), behind `config/features.json` flags (`studioV2`, `quickRecap`, `labs.*`; data, read at start). Self-test → "Preview features" turns flags on in a test APK (saved in app settings, overrides the file). D-42 Live preview (2026-11-13, spec §4): Story and Style show the movie in Media3 ExoPlayer (desktop: VLC if installed, D-16, else frames) with the layers and captions drawn on top in Compose — same rects, same Burmese font file, same line breaks (`CaptionChunks`); drag / pinch edits a rect. Compose text shaping is not libass, so the preview is close but not exact: "Exact frame" renders the current frame with the export compiler (`ffmpeg -ss t … -frames:v 1`, `.cache/frames/`) and pre-flight shows such frames. Reason: a full render is slow on the owner's phone (21.5 s of 1080p took 30.1 s, PLAN 1F — a 10-minute recap ≈ 14 minutes), so the style must be judged without rendering. Spike S10 checks preview vs export positions in CI.

D-43 Embedded subtitles (2026-11-13, spec §7): the Source step lists the movie's subtitle tracks (ffprobe: index, codec, language, title). Text tracks (subrip, ass / ssa, mov_text, webvtt) are extracted offline by the bundled ffmpeg into `source/subtitles.srt` (`-map 0:s:<n> -c:s srt`, written to `.part`, then renamed; the native codecs are in the build — tools/ffmpeg-android/build.sh disables only autodetect, network and devices); a previous file moves to `.cache/replaced/`. Picture tracks (PGS, VobSub, DVB) cannot be read as text: the card says so and offers Transcribe (D-44). Free, no quota.

D-44 Scene audio transcription (2026-11-13, spec §7; amends D-33 "script input"): with no subtitles, "Transcribe picked scenes" sends only the audio of the picked scenes — never video, never the whole movie, no Files API — to the existing `GeminiTranscribeProvider` (D-31): ffmpeg cuts the picked ranges and joins them into mono 16 kHz AAC ≈ 32 kbit/s chunks of at most 10 minutes (≈ 2.4 MB, inside the D-31 inline limit); the prompt lists each scene's start / end in chunk time, and the answer `{scenes:[{scene, lines:[{start, end, text}]}]}` (the movie's language) is mapped back to movie time and saved as a `tx` artifact (`source: "gemini-scenes"`) in `recap.sources.transcript`. A confirm card first shows the requests (usually 1–2) and today's usage. The script writer uses these lines like `.srt` lines (≤ 600 characters per scene); scenes picked later are transcribed alone. Whole-movie transcription stays Labs.

D-45 Burmese voices besides Gemini (2026-11-13, Q-14 open): the Thiha (male) / Nilar (female) neural voices through Azure AI Speech REST (`AzureTtsProvider` in `:ai`: Ktor + SSML, no SDK; key + region in secure storage; voice ids in `config/models.json` `tts.azure`) — an official API with a free F0 tier, BYOK like Gemini, hidden until a key is saved; they follow the voice lock (D-35). The Edge "Read aloud" endpoint is unofficial and may stop working at any time, and recaps are made to be published, so it is only a Labs switch (off) and never a default. Rejected: RVC / Colab voice cloning (needs a PC or a GPU session; D-22).

D-46 Smart Fit (2026-11-13, spec §8; amends recap.md §6): when a take is longer than its block, the block offers fixes in this order: (1) trim silences in the take (gaps > 350 ms → 200 ms, a derived `au` take), (2) "Shorten text" (Gemini rewrite, applied only after the owner approves; new `rs`, the take turns ⚠ Stale), (3) extend — the movie runs on (today's rule) or the next movie range is added, (4) speed — voice `atempo` up to `maxVoiceSpeed`, picture slow-down down to `maxVideoSlow`, (5) freeze the last frame. The limits are data in `config/recap.json` and start at 1.0 (off) until spike S8 (the owner listens to Burmese takes at 1.05–1.25× on the phone): the 1.15–1.25× limits other apps use are not measured for Burmese. Default fix = extend (current behaviour); the choice is saved per block in `recap.fit`.

D-47 Quick Recap (2026-11-13, spec §10): Home → Quick Recap is a wizard over the same v2 data and `RecapRules`, not a second pipeline: movie → length (1 · 3 · 5 · 10 min) → style (Brand Kit / preset) → Start. Afterwards it is a normal Recap project, so every step stays editable.

D-49 Built-in Burmese fonts (2026-11-14, owner request): the app ships Pyidaungsu 2.5.3 (Regular, Bold; Myanmar government font, free to use and share) and Noto Sans Myanmar (Regular, Bold; SIL OFL 1.1, `fonts/NotoSansMyanmar-OFL.txt`) as base64 text in `fonts/*.ttf.b64` (so they can be committed through the GitHub API), decoded by `decodeBuiltInFonts` into Android assets `fonts/` / desktop resources `/config/fonts/` (~0.8 MB in the app). On first use they are copied into `<app dir>/fonts/` (files, because Android `Font(File)` and libass `fontsdir` need files) and added after the Settings fonts, so `UiFont` / lyric and caption overlays pick Pyidaungsu, else Noto, with no setup. This fixes the open note that Android may clear picked fonts from the cache. No new dependency.

D-50 Recap picture and caption style on the v1 recap (2026-11-14; amends D-37 for blur masks): blur boxes that hide the movie's own subtitles or logos are stored in `recap.visual.masks` with rects in 0–1 of the **movie picture**, not of the output frame, and are drawn on each movie clip before the looks and the fit (split → crop → `gblur` → overlay). Reason: the same box then covers the same words at 16:9, 9:16 or 1:1, with or without Zoom / Mirror; an output-frame rect would move off the subtitles whenever the ratio or the bars change. The space around a movie whose shape differs from the video's is `recap.visual.background`: black bars (as before), the movie blurred (blurred at a quarter size, then scaled up — cheap on the phone) or a colour; Fill frame still crops. Captions are centred on the lowest box in the lower half when "captions on the box" is on. Caption style (`recap.captionStyle`: Small / Medium / Large × 0.85 / 1 / 1.2, white / yellow / cyan, outline or a see-through dark box = ASS BorderStyle 3) also changes the characters per line, so the burned-in and `.srt` chunks stay the same. Both live on the v1 recap (copied by the 1 → 2 migration) until the v2 reader lands. "Cut long pauses" (5B-4) runs `silenceremove` once when a take is made (a WAV take with its real length), never at render time, so the fit check matches the video.
