# Decisions (ADR-lite). Do not reopen without a new entry.

D-01 KMP + Compose Multiplatform over Flutter — owner's Kotlin expertise, YFT code reuse.
D-02 Project-as-folder with immutable content-hash artifacts; SQLite only as index.
D-03 Stale detection via recorded inputs, not status cascades.
D-04 Video generation is manual via Google Flow. No automation of Google UIs — ToS/account risk and brittleness.
D-05 Gemini API free tier (AI Studio key) for text/image/TTS. AI Pro subscription is NOT an API credential; it only applies to Flow/AI Studio UI.
D-06 No backend, accounts, billing, or custom sync. Syncthing/folder copy is the sync method.
D-07 Desktop video playback: VLCJ first. Fallback if spike S3 fails: ffmpeg-extracted thumbnails + "open externally", playback deferred.
D-08 ~~Android does not render. ffmpeg-kit is retired; Media3 Transformer only for preview concat if ever needed.~~ Amended by D-22/D-23 (2026-11-11): Android renders; ffmpeg-kit stays retired.
D-09 Voice replication is an optional, capability-gated feature. Default narration path is user recording; standard TTS second.
D-10 Model names/quotas/credit costs live in `config/models.json`, never in code.
D-11 Koin for DI (KMP). kotlinx.serialization for all persisted models.
D-12 Burmese text for humans, English for models; separate fields, never auto-translated silently.
D-13 Toolchain pinned as one set in `gradle/libs.versions.toml` only: Kotlin 2.4.21, Compose Multiplatform 1.12.2, AGP 9.3.3, Gradle 9.7.1, kotlinx.serialization 1.12.0, coroutines 1.11.0, Ktor 3.6.1, Koin 4.2.2 (newest set inside Kotlin 2.4.21's tested Gradle/AGP range); shared modules use `com.android.kotlin.multiplatform.library` + `jvm("desktop")`; JVM target 17, minSdk 26, compileSdk 37; no Material3 (custom theme per DESIGN.md); upgrade versions together as a set.
D-14 Reference images: manual handoff by default — copy the ImageDialect prompt, generate in the AI Studio UI or Flow (covered by the AI Pro subscription), import the file as Ref A/B. `GeminiImageProvider` is optional and capability-gated: a probe that returns 429 with `limit: 0` marks it unavailable. Reason: spike S2 — every Gemini image model has zero free-tier API quota, and D-05/D-06 rule out API billing.
D-15 GeminiTextProvider resilience: the model fallback chain is the stage's ordered `candidates` list in `config/models.json` (never in code), applied at every stage call; exponential backoff on 500/503 (and on 429 when `retryDelay` ≤ 60 s); request timeout 120 s per attempt, and every running AI call shows a Cancel button; app-side daily request counter, because the API returns no rate-limit headers. Reason: spike S1 — `gemini-2.5-flash` refused for new keys, `gemini-3.8-flash` mostly 503, and 3.5-flash 503 on about half of calls. (Amended 2026-11-10: timeout 300 s → 120 s + Cancel; chain source = `candidates`.)
D-16 VLC is not bundled. Playback uses a separately installed VLC 3.0.x (64-bit): Settings → "VLC path", auto-detected at `C:\Program Files\VideoLAN\VLC`. If VLC is not found, show an "Install VLC" link (videolan.org) and disable playback; shots show ffmpeg-extracted thumbnails only. Reason: spike S3 — even a trimmed VLC adds ≈95 MB to the installer plus LGPL/GPL plugin licensing; VLCJ JARs (3.7 MB) stay in the app. Closes Q-05.
D-17 Test-only libraries: `kotlinx-coroutines-test` (virtual time for retry/backoff and fake-delay tests) and `ktor-client-mock` (HTTP-free provider tests). Versions come from the D-13 `kotlinx-coroutines` / `ktor` refs; never on a main classpath.
D-18 File access: `:core` owns the small `core.io.FileSystem` port (exists/createDirectories/list/read/writeDurably/atomicMove; `watch` added with the Inbox in 1C-d) with `InMemoryFileSystem` for tests. `:platform` implements `JvmFs` (java.nio: `FileChannel.force` + `ATOMIC_MOVE`) in a source set shared by desktop and Android, which adds the `:platform → :core` edge. Android SAF arrives in 1F (optional, D-25) as another implementation; `:core` does not change. Closes Q-06.
D-19 API key storage on Windows: JNA (`jna` + `jna-platform` 5.17.0, desktop only) for DPAPI `CryptProtectData` (current-user scope); `SecureStorage` keeps the encrypted blob in `~/.autoflow/secrets.bin` (atomic write). Simpler than Credential Manager with the same per-user binding. Other desktop OSes report `Unsupported` (no env-var fallback, AGENTS.md §1), so Real AI mode needs Windows. Android: see D-25.
D-20 Amends D-02: the project index is a rebuildable JSON list `~/.autoflow/projects.json` (path, name, mode, ratio, progress, last opened), not SQLite, until project counts need more. No new dependency; losing it loses no data (re-open the folders).
D-21 A shot whose spec id changes (regenerate all/one, edit, version switch) loses only its storyboard approval; prompt/ref/video pointers and approvals stay and show as stale (specs/workflow-and-approval.md "Approvals are not auto-cleared"). Storyboard versions (`sb`) are whole-song generations; per-shot regenerates and edits record `inputs.storyboard` = the current version and are not added to it.
D-22 Android is a first-class target, equal to desktop (2026-11-11): the owner has no PC, so the phone does everything — Gemini API, Flow in the mobile browser, import, render, export. The Phase 3 "companion" scope is replaced by full feature parity (PLAN 1F); Windows stays supported and is verified by CI only. Amends D-08: Android renders. On-device testing has no adb: the owner installs a CI-built APK (D-24) and pastes back a report the app writes (Self-test, PLAN S6; crash text on the next launch).
D-23 Android rendering runs a bundled ffmpeg executable, driven by the same RenderGraph → filtergraph compiler as desktop (one compiler in `:media` commonMain). The binary is `app-android/src/main/jniLibs/arm64-v8a/libffmpeg.so` (plus `libffprobe.so`), packaged with `useLegacyPackaging = true` so Android extracts it to `applicationInfo.nativeLibraryDir` — the only app location Android 10+ (targetSdk ≥ 29, W^X) lets an app exec — and started with `ProcessBuilder`. Source: built by our CI (`tools/ffmpeg-android/`) from upstream release tarballs pinned by SHA-256 (FFmpeg 9.0.2 with libx264, libass + freetype + fribidi + harfbuzz, native `aac`; no fontconfig: fonts come only from `fontsdir`, specs/render-graph.md), NDK r29, arm64-v8a, API 26, PIE against bionic, third-party libraries static; not committed (binary), cached in CI. License: GPL-2.0-or-later (libx264), license texts and the build info (configure line, source URLs, hashes) ship in the APK. Size: ≈ 25 MB each for `libffmpeg.so` and `libffprobe.so` uncompressed (first build 2026-11-11; exact bytes, SHA-256 and linked system libraries are in the APK `assets/ffmpeg/BUILDINFO.txt` and the CI "Bundled ffmpeg" notice); only Android system libraries are linked dynamically. Why not a download: ffmpeg-kit is retired (D-08) and static glibc Linux builds risk being killed by Android's app seccomp filter. If the from-source build cannot be made to work, a pinned Termux ffmpeg package (libass) is the recorded fallback. Media3 Transformer 1.11.1 (`media3-transformer`, `media3-effect`, `media3-common`) is a fallback only if exec is blocked on the owner's device; the Self-test runs it when exec fails. Verified 2026-11-11 (S6 PASS on the owner's Android 16 phone, spikes/s6-android-selftest/README.md): exec is the render path.
D-24 Every CI push builds a debug APK and uploads it as the Actions artifact `autoflow-debug-<sha>.apk`; a tag `v0.*` attaches it to a GitHub Release so the owner downloads it on the phone. The agent cannot push tags, so a change to `.github/release-tag.txt` on `main` makes that CI run create the tag and the release (tags made with the workflow token start no new workflow runs). Signing: one stable key from Actions secrets (`ANDROID_KEYSTORE_B64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`), never committed, so every APK installs over the previous one and app data survives; without the secrets the build falls back to the runner's debug key and says so in the APK's build info. `versionCode` = CI run number.
D-25 Android platform choices: playback = Media3 ExoPlayer (no VLC on Android, D-16 is desktop only). Secure storage = Android Keystore AES-256-GCM key (non-exportable) encrypting the existing `FileSecureStorage` blob — the platform API directly, not `androidx.security:security-crypto` (deprecated). Project folders live under the app's external files dir by default (no SAF needed); SAF "Open folder" is optional later. Uninstalling deletes that dir, so Settings gets "Backup all projects" (zip → share sheet) (PLAN 1F). Secure-storage details (2026-11-11): the cipher is `AesGcmCipher` (`:platform` jvmShared, so it is tested on the JVM with a software key): `secrets.bin` = `AFS1` · version `1` · 12-byte IV (chosen by the Keystore) · ciphertext + 128-bit tag, with a fixed AAD; key alias `io.github.alalkipgen.autoflow.secrets.v1`, no user authentication (renders and the AI run without unlocking). The key never leaves the phone, so `secrets.bin` is excluded from Auto Backup and device transfer (manifest rules); a file without its key reads as unreadable and the next save replaces it with a new key.

D-26 Android render scheduling (2026-11-11): AndroidX WorkManager 2.12.0 runs renders as durable background work in its foreground service (progress + Cancel notification; `mediaProcessing` type on Android 15+, `dataSync` before). WorkManager brings Room, AndroidX Startup and lifecycle-service transitively. One unique chain `render` (APPEND_OR_REPLACE) keeps renders one at a time and in order. A failed or cancelled WorkManager work fails or cancels every work queued behind it, so (1) every render ends as a succeeded work with its outcome (done / failed / cancelled) in the output Data, and (2) Cancel never calls WorkManager's cancel: a per-job marker (`filesDir/render-jobs/<id>.cancel`) makes a queued job skip itself, and the running render's coroutine is cancelled in-process, which kills ffmpeg; the worker returns only after that, so two renders never overlap. When WorkManager itself stops the worker, the cancellation is rethrown and WorkManager retries it. The job JSON lives in `filesDir/render-jobs/<work id>.json` (Data is limited to 10 KB) and is deleted only when WorkManager no longer lists the work as unfinished and the file is over an hour old, so a retry after process death still finds it. Rejected: one long-running drain worker over our own queue file (a second source of truth beside WorkManager). Tests are JVM unit tests with fakes; `kotlin-test-junit` (test only, JUnit 4 for Android local unit tests) is the only added test dependency.

D-27 Android project storage and backup (2026-11-11, details D-25): new projects go to `<external files dir>/projects/<name>.autoflow` (`AppDirs.projectsHome`; the internal files dir if there is no external storage) without a folder choice; the Dashboard hides "Open folder…" and adds `*.autoflow` folders it finds there to the list, so a lost `projects.json` or a restored backup reappears. Settings → Backup zips every listed project whose `project.json` exists (`ProjectZip`, java.util.zip: `<folder>.autoflow/…` + `autoflow-backup.json` manifest; leaves out `.cache/`, `*.part.*`, `*.tmp`; media stored, text deflated) straight into `Download/AutoFlow/AutoFlow-backup-<yyyyMMdd-HHmmss>.zip` through MediaStore (Android 10+, no storage permission, visible in the Files app, kept after an uninstall; older Android reports Unsupported), with a free-space check first and the half-written file deleted on failure or Cancel; "Share…" then sends that file to the share sheet. Saving to Download instead of a cache file + share sheet only means one uninstall-proof copy always exists. Restore arrives with the system file picker (PLAN 1F). No new dependency.

D-28 CI build-machine ffmpeg (2026-11-11): the android job gets the x86-64 ffmpeg for the S6 self-test media from a pinned static build (johnvansickle.com ffmpeg 7.0.2-static, GPL, SHA-256 checked; libx264, libmp3lame, libass) via `tools/ci-ffmpeg.sh`, with bounded apt (`tools/ci-apt-install.sh`) as the fallback. Why: the Ubuntu apt mirror hung every android job on 2026-11-11. CI only — nothing is shipped in the app; the phone keeps the D-23 bundled ffmpeg.

D-29 Prompt staleness inputs (2026-11-12, Q-10, owner approved): a compiled prompt (`pr`) records `spec`, `globalStyle` and — new — `characters` = `"<sorted tokens>|ch_<12 hex>"` (the tokens the shot uses and a SHA-256 of their current English descriptions), so changing a character's description marks exactly the prompts that use it ⚠ Stale. When a recompile produces bytes identical to an existing `pr` artifact (dedupe), `ArtifactStore.recordInputs` rewrites only that sidecar's `inputs` (atomic); data files stay write-once. Rejected: hashing all characters (one edit would stale every shot).

D-30 Lyric line timings (2026-11-12, Q-11, owner approved): the song's line timings are one `tx` artifact (`LyricTimings {schemaVersion, source: "tap"|"gemini", lines: [{text, startMs, endMs}]}`, song time) pointed to by the new optional `project.lyricTiming` (no schema bump: the field defaults to null). Lines = the lyrics' non-blank lines without `[Section]` markers. They are used only while they match the current lyrics lines; otherwise Export falls back to each shot's `lyricsMy` and says so. Importing another song clears the pointer. With timings, Export shows one overlay per line at its own time (cut at the video's end) instead of one per shot; shot cut points do not change (snapping cuts to line starts is a later option). Tap-to-sync: a line ends where the next starts, at most 10 s; the last ends at an extra "end" tap (else 6 s, cut at the song end); taps < 150 ms apart are ignored. Desktop has no audio player (no VLC binding), so tap-to-sync is Android-only for now.
