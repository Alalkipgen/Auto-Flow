## Evidence gates

- Use temp projects and unchanged-byte assertions for browse-only/destructive tests. Pending phone steps are in [PHONE-QA](../PHONE-QA.md).
- Live Gemini is local, opt-in and synthetic only. Check the models list first; on invalid credentials stop and document a redacted reason. No key, prompt or response content in source, logs, CI, public artifacts or this spec. Fakes remain the regular test path.
- Record fresh remote SHA, test results and artifact identity. Neither this audit nor the attached baseline evidence establishes a pass on the new stack.

F1 synthetic reproduction: the production 540p renderer and `ffprobe` agreed at 16:9 = 960x540, 9:16 = 540x960, 1:1 = 540x540. These are test projects, not the owner’s clip. No renderer settings changed.


F2 final map: **Small 13%**, **Medium 22% (legacy)**, **Large 35%**, **Custom 5–55%** of output width. The 55% ceiling is 2.5× Medium. Standard FFmpeg IMAGE scaling already supports this range; only the watermark's own width is clamped. Brand Kit saves an optional width; old projects and kits still use the exact legacy geometry. See D-75 for inherited anchor/clipping limits.


F4 Remove persists a canonical folder exclusion in the recents index. A same-name project in another folder is independent. Passive scans and saves cannot clear an exclusion; explicit Open or Restore to Projects can. Restoring a separately exported archive still registers the actual restored destination, not the original path.


### F4 follow-up — Option B (owner phone feedback)

Cause on build 679 (`ded336b`): the active-card menu hid Delete if the guard found **any** file under `artifacts/` or **any** ZIP. The Removed picker could only reopen a project. Bare creation makes empty artifact directories; the generic phone message does not identify the file found. Neither age nor display name was an eligibility check.

An active card keeps tap-to-open and the existing long-press Remove confirmation. `Removed projects…` lists excluded managed folders; picking one offers **Restore to Projects** (index only) and **Delete permanently…** when eligible. Delete confirmation shows the project name, path, measured project-file bytes and irreversibility. Safe old and new folders are eligible even with work inside. D-76 allows deleting their project-owned files, including artifacts, only when the user confirms this whole-project operation. Existing ZIPs and migration snapshots, if present, are relocated byte-for-byte to a unique folder under `retained-backups/` beside the project, not deleted or auto-generated.

Keep the immediate canonical app-managed child, manifest identity/revision, no-link/nested-project, queue and write-lease checks. SAF and arbitrary desktop folders remain Remove-only. A deleted project disappears from both lists without reappearing on restart; old Jobs entries remain marked `Project deleted`. Test only disposable folders. Implementation touches the Dashboard model/screen/strings, platform deletion guard, project tests and the F4 docs (UI v3 §6, original brief §7, D-76).

F5 long-press, secondary click, or the accessibility action opens a context choice and then confirmation. Tap / Apply still copies style. Saved entries have no saved-date field; built-in workflow options are not Library records. Deletion re-reads the selected ID and removes only that saved entry, not shared bytes or anything already copied into a project.

F6 the Jobs-only action is available on Done, Failed and Cancelled AI/render rows. AI history loses its persisted payload and retains only an ID tombstone, preventing a delayed observer or worker from recreating the record. Completed render rows use a separate app-owned dismissal index; the queue, output and Export metadata stay untouched. Existing renders are not newly promoted into a permanent all-renders log. No bulk clear.

### F3 follow-up — Gemini progress where the request starts

Source audit at `e437eef`: Music Video Input expected the shell's `JobBanner`, but only the legacy shell mounts it. Studio v2 shows the same `StoryboardJobs` label in Jobs, not on the Project page. The Jobs row also used the label as its ID, with no project or return route. Storyboard generation has **two logical stages** (lyrics analysis, then one JSON batch for the actual split shots); the present generator does not stream or send one request per shot. Regenerating one shot is a single stage. Report these actual stages with an indeterminate bar, elapsed time and the existing retry countdown; never claim per-shot completion during a batch. Manual Flow, beat detection and prompt compilation are not Gemini calls.

Scope (F3, UI v3 §6/§9, `specs/ai-providers.md`): `StoryboardJobs`/`StoryboardService`, the shared Jobs row/card/actions, Input/Storyboard launch, Project/legacy shell and the project busy check; fake-provider and real-pointer tests. Display only the originating open project on the Project page, reuse the same app-scope run in Home/Jobs, and keep the existing entry points and output format. An in-memory run survives screen changes, not process death; saved results still reopen normally. Provider/model, prompt, batching, concurrency, pacing and persistent job/output formats do not change. Lyrics timings, Recap single-block voice and Settings diagnostics are separate call sites to audit and cover in the follow-up slices.


Music Video lyric suggestions previously showed a fixed “up to 2 minutes” label inside a route-scoped coroutine, with no Cancel or Jobs row; leaving Input cancelled the waiter. Bind the actual one-request action to the same project-owned run as Storyboard, display media preparation and Gemini wait/retry from the real trace, and show the saved timings on return. Settings’ key and TTS checks previously shared one Boolean and could call the key check “Testing” while TTS ran. Give each diagnostic a correctly named shared card with Cancel; these non-project checks still belong to Settings and stop when it closes, not to project Jobs. Scope: `InputModel`, `LyricSyncModel`/card, shared Gemini launcher, `SettingsModel`/screen, bilingual labels and fake-provider regressions. No request, model or saved format changes (F3, D-31, D-34, UI v3 §6/§9).
